# Проверка сети на Android

Подключите телефон по USB с включённой отладкой. Для автоматического сравнения установите debug APK клиента и тестовый APK. В клиенте должны быть рабочие узлы и уже выданное разрешение Android на VPN. Перед тестом отключите VPN. Перебор политик работает поверх текущих настроек телефона и не меняет сохранённую политику. Для сравнения пулов снимите ручную фиксацию узла в клиенте.

```powershell
cd android
.\gradlew.bat :app:assembleDebug :app:assembleDebugAndroidTest
# Установите debug APK для архитектуры телефона из app/build/outputs/apk/debug.
# Установите тестовый APK из app/build/outputs/apk/androidTest/debug.
python check_network.py --compare --label phone --repeat 2 --policy BALANCE --policy LATENCY --policy STABLE --policy SMART --lan-ip 192.168.0.1 --expect ya.ru=DIRECT --expect www.gosuslugi.ru=DIRECT --expect vk.com=DIRECT --log ../artifacts/network/phone.jsonl
```

Укажите адрес своего роутера или другого известного устройства. `--lan http://192.168.0.10:8080/` проверяет также доступность конкретного локального HTTP-сервиса. `--site https://example.org/` добавляет сайт. Повторяйте параметры для нескольких адресов. `--serial` выбирает телефон, когда подключено несколько устройств.

Укажите ожидаемый выход с учётом ваших правил. Чтобы проверить пользовательское исключение поверх списка RU, задайте правило в клиенте, добавьте сайт через `--site` при необходимости и укажите `--expect имя-хоста=PROXY` или `--expect имя-хоста=DIRECT`.

Тест сравнивает исходную сеть, трафик телефона через TUN и HTTP-прокси ядра. В журнал записываются код HTTP, этап ошибки, замеры DNS/TCP/TLS и, при наличии, правило и выход Mihomo для проверяемого хоста. Проверки маршрутов подтверждают интерфейс для публичного IP, DNS и указанных LAN-адресов. Отсутствие ответа ICMP само по себе не считается ошибкой, поскольку устройство может фильтровать ping. Тест загружает страницы и не проверяет вход в аккаунт или воспроизведение видео.

Для пяти встроенных сайтов HTTP 200 засчитывается после проверки конечного домена, типа содержимого и нескольких признаков настоящей страницы. Известные заглушки и CAPTCHA получают `block_or_challenge`, неожиданный конечный домен — `unexpected_redirect`. Если признаков мало или ответ превышает 2 МиБ, результат остаётся неподтверждённым. Для дополнительных URL измеряется доступность, в журнале стоит `content_check: not_checked`. Тело страницы в журнал не пишется.

При запуске без `--compare` тест использует текущее состояние телефона. Нужен `curl` в Android shell. Код завершения 1 означает, что хотя бы один запрос или проверка маршрута с VPN завершились ошибкой. Ошибки базового прогона без VPN сохраняются для сравнения. Код 2 означает, что тест не удалось провести.

## Проверка отказов и восстановления

Из корня проекта запустите:

```powershell
python android/check_resilience.py --phone --log artifacts/network/resilience.jsonl
```

Проверки HTTP, DNS и резервного переключения поднимают локальные заглушки и отдельный Mihomo с временной конфигурацией. Для сценариев без телефона уберите `--phone`. Для другой сборки Mihomo укажите `--core`. Параметр `--gateway` задаёт адрес роутера для проверок маршрута и ping.

`--transitions` переключает Wi-Fi и мобильные данные на телефоне по USB и восстанавливает исходные настройки в конце. Начните с подключённого Wi-Fi и выключенного VPN. По умолчанию при исходно выключенных мобильных данных тест проверяет полный обрыв и возврат Wi-Fi. `--try-cellular` временно включает данные для проверки мобильного интернета. `--vpn-transitions` повторяет потерю связи и смену сети внутри одной VPN-сессии. Для этого установите debug APK и тестовый APK, добавьте узлы и один раз разрешите VPN.

```powershell
python android/check_resilience.py --phone --transitions --try-cellular --vpn-transitions --log artifacts/network/resilience-handover.jsonl
```

Каждый сценарий сохраняет время, результат и наблюдение в JSONL. `fail` означает несоответствие ожидаемому поведению. `skip` содержит причину пропуска. Код завершения 1 означает, что есть хотя бы один `fail`.

## Случайные отказы узлов

```powershell
python android/check_resilience.py --chaos 50 --seed 20261113 --chaos-only --log artifacts/network/node-chaos.jsonl
```

Тест поднимает три локальных узла и отдельный Mihomo. Выбранный узел внезапно отключается или возвращает HTTP 200 с оборванным телом. Каждый восьмой раунд выключает весь пул и возвращает один узел. Один и тот же seed воспроизводит последовательность отказов.

Тест параллельно запускает GET-проверки, выбирает самый быстрый узел с полным ответом, переключает группу Mihomo и делает через неё ещё один запрос. При полном отказе группа отклоняет запрос. Это эксперимент на стенде. Политика установленного клиента не меняется. Проверка смены сети отдельно записывает время и выход Mihomo для прямого запроса к ya.ru и запроса к YouTube через VPN.
